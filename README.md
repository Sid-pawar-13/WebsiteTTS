# WebsiteTTS

**Listen to the web, not just read it.**

A lightweight Manifest V3 browser extension that turns webpage text into speech using local **Ollama Phonon** or an **OpenAI-compatible TTS API**.

Read articles, documentation, and online lessons with paragraph-by-paragraph playback, automatic scrolling, and visual highlighting.

## Overview

WebsiteTTS extracts readable text from the current webpage and sends it to your selected text-to-speech provider. It plays the generated audio while keeping your reading position visible.

Choose local speech generation with Ollama and Phonon, or connect a hosted or self-hosted service that implements the OpenAI-style speech endpoint.

> **Your provider, your choice:** WebsiteTTS does not bundle a speech model. Audio is generated by the provider endpoint configured in Settings.

## Features

| Feature | What it does |
| --- | --- |
| Two TTS providers | Local Ollama Phonon or an OpenAI-compatible API |
| Reading controls | Start, stop, previous paragraph, and next paragraph |
| Visual reading position | Highlights the current text block and scrolls it into view |
| Embedded-frame support | Collects readable content from accessible page frames |
| Adjustable playback | Browser playback speed from 0.7× to 2.0× |
| Persistent preferences | Remembers provider settings, selected provider, speed, and theme |
| Independent provider settings | Keeps Ollama and OpenAI-compatible configurations separate |
| API connection test | Generates and plays a short test phrase before saving |
| Light and dark themes | Shared theme preference across the popup and Settings page |
| Temporary audio handling | Uses in-memory audio and temporary object URLs instead of persistent audio files |

## Requirements

- A Chromium-based browser with Manifest V3 support. See [Browser compatibility](BROWSER_SUPPORT.md).
- One working speech provider:
  - **Ollama:** Ollama 0.40.9 or later and the Phonon model. The current Phonon model page specifies Apple Silicon; check its documentation for current platform support.
  - **OpenAI-compatible API:** A server implementing the OpenAI-style speech endpoint, a supported model and voice, and an API key.
- Internet access when using a hosted API. A local Ollama server can generate speech without sending text to a hosted TTS service.

No Node.js, npm install, compilation, or build step is required to install or run the extension.

## Installation

### 1. Download WebsiteTTS

Choose either option:

- **Latest release:** Download the Chromium ZIP from [GitHub Releases](https://github.com/Sid-pawar-13/WebsiteTTS/releases).
- **Development copy:** Clone the repository:

      git clone https://github.com/Sid-pawar-13/WebsiteTTS.git
      cd WebsiteTTS

If you downloaded a release ZIP, extract it into a permanent folder. The folder you select in the browser must contain manifest.json at its top level.

### 2. Load the extension

1. Open the browser's extensions page:
   - Chrome: chrome://extensions
   - Edge: edge://extensions
   - Brave: brave://extensions
   - Opera: opera://extensions
2. Enable **Developer mode**.
3. Select **Load unpacked**.
4. Choose the WebsiteTTS folder containing manifest.json.
5. Confirm that WebsiteTTS appears in the installed extensions list.
6. Pin the extension to your toolbar for convenient access.

> **Note:** This is a developer/sideload installation. For ordinary users, install from the official browser store listing once it has been published and approved.

### 3. Configure a provider

Open WebsiteTTS from the toolbar, choose a provider from the dropdown, and open **Configure TTS provider and API**.

Enter the endpoint, model, voice, and API key where required. Follow the provider guide below.

### 4. Start listening

1. Open a webpage containing readable text.
2. Click the WebsiteTTS toolbar icon.
3. Select your configured provider.
4. Set the reading speed.
5. Press **Play**.

The extension highlights the current text block and scrolls it into view as playback progresses.

## Configure a speech provider

Open Settings using the gear icon or the **Configure TTS provider and API** link in the popup.

### Option A: Ollama and Phonon (local)

This option sends speech requests to an Ollama server running on your machine.

#### 1. Install and prepare Ollama

Install [Ollama](https://ollama.com/download). The current integration requires Ollama **0.40.9 or later**.

On macOS, allow the browser extension origin before launching Ollama. Open Terminal and run:

    launchctl setenv OLLAMA_ORIGINS "chrome-extension://*"

Then:

1. If Ollama is running, fully quit it.
2. Run the command above in Terminal.
3. Launch Ollama again so that it inherits the environment variable.
4. Pull the Phonon model:

       ollama pull phonon

You may need to repeat the launchctl command after logging in again. The command shown here is for macOS; other operating systems use different methods to configure environment variables.

For tighter origin permissions, replace the wildcard with this extension's specific chrome-extension://<extension-id> origin. See the [Ollama CORS FAQ](https://github.com/ollama/ollama/blob/main/docs/faq.mdx#how-do-i-allow-additional-web-origins-to-access-ollama).

#### 2. Enter the WebsiteTTS settings

Select **Ollama (local / Phonon)**. The default values are:

| Setting | Value |
| --- | --- |
| API base URL | <code>http://localhost:11434/v1</code> |
| Model | <code>phonon</code> |
| Voice | <code>default</code> |
| API key | Not required |

#### 3. Test and save

1. Select **Test API**. WebsiteTTS sends the phrase “Hi! This is a test.” and checks that Ollama returns non-empty WAV audio.
2. Confirm that you hear the test sound.
3. Select **Save configuration**. This runs the test again and saves the settings only if it succeeds.

**Audio format and speed:** WebsiteTTS requests WAV from Phonon. Phonon currently supports API speed 1 only, so the extension applies the speed slider during browser playback. The slider changes playback speed; it does not change Phonon's synthesis speed.

### Option B: OpenAI-compatible API

Use this option with OpenAI or a self-hosted service that implements the OpenAI-style speech endpoint and request schema.

#### 1. Enter the provider settings

Select **OpenAI-compatible API**, then provide:

| Setting | Description |
| --- | --- |
| API base URL | Your provider's API base URL, for example <code>https://api.openai.com/v1</code> |
| Model | The speech model identifier accepted by your provider |
| Voice | A voice identifier supported by that model |
| API key | The credential required by your provider |

The default OpenAI values are:

| Setting | Default |
| --- | --- |
| API base URL | <code>https://api.openai.com/v1</code> |
| Model | <code>gpt-4o-mini-tts</code> |
| Voice | <code>alloy</code> |

Enter either the API base URL or the complete /audio/speech endpoint. WebsiteTTS appends /audio/speech when it is not already present.

#### 2. Test and save

1. Select **Test API**.
2. WebsiteTTS sends a short speech request and expects a non-empty audio response.
3. Confirm that the test audio plays.
4. Select **Save configuration** to test once more and persist the configuration.

The extension requests MP3 audio and sends the selected playback speed as the API speed parameter. Your provider must support the endpoint, model, voice, authentication method, and request fields used by WebsiteTTS. An OpenAI-style URL alone does not guarantee compatibility with every provider or model.

## Using WebsiteTTS

Open the WebsiteTTS popup while viewing the page you want to hear.

| Control | Action |
| --- | --- |
| **Play** | Starts reading from the current position. If playback has finished, it starts again from the beginning. |
| **Stop** | Stops speech playback and clears the current highlight. |
| **Previous** | Moves back by one extracted text block and reads it. |
| **Next** | Moves forward by one extracted text block and reads it. |
| **Reading speed** | Adjusts playback speed from 0.7× to 2.0×. |
| **Provider** | Switches between the saved Ollama and OpenAI-compatible configurations. |
| **Theme** | Switches between light and dark appearance. |
| **Settings** | Opens the provider configuration page. |

WebsiteTTS reads one extracted block at a time. Long blocks are split into smaller text chunks before speech generation. The page scrolls to and highlights the block being read.

## Settings and audio lifecycle

WebsiteTTS stores preferences using chrome.storage.local in the browser profile.

| Data | Where it is kept |
| --- | --- |
| Provider configurations | Local extension storage |
| OpenAI-compatible API key | Local extension storage |
| Selected provider | Local extension storage |
| Reading speed and theme | Local extension storage |
| Generated speech | In memory during synthesis and playback |

The Ollama and OpenAI-compatible configurations are stored separately. Switching providers does not overwrite the other provider's saved configuration.

### Audio lifecycle

WebsiteTTS does **not** save generated section audio as a persistent file. The speech response is temporarily passed from the extension background worker to its offscreen audio document. The audio document creates a Blob and a temporary object URL for playback.

Temporary audio resources are cleared and the object URL is revoked when playback ends, is stopped, is replaced by another clip, or fails. The Settings page's API test player follows the same cleanup approach, including when the page is closed.

## Privacy and permissions

WebsiteTTS needs broad page access to read text on the websites where you choose to use it.

| Permission | Why it is needed |
| --- | --- |
| activeTab | Interact with the tab where you start reading. |
| storage | Save provider settings, API credentials, theme, and reading speed locally. |
| offscreen | Play generated audio outside the webpage context. |
| webNavigation | Discover accessible frames so embedded page content can be collected. |
| <code>&lt;all_urls&gt;</code> host access | Inject the reader into pages and frames across websites. |

**Understand where your text goes:**

- With **local Ollama**, text is sent to the Ollama endpoint you configure (localhost by default). Your local server processes the speech request.
- With an **OpenAI-compatible provider**, extracted webpage text is sent to the API endpoint you configure. Review that provider's privacy and retention policies before use.
- WebsiteTTS stores API keys in browser extension local storage. This is convenient, but it is **not a secure secret vault**. Someone with access to your browser profile or extension developer tools may be able to retrieve the key.
- For shared devices or production deployments, consider routing requests through a private backend rather than storing a long-lived API key in the browser.
- WebsiteTTS does not create a persistent audio file for each section. This does not change the data-retention practices of the speech provider.

Install the extension only from a source you trust. Broad host permission is required for its core purpose, but it should be treated as a meaningful permission.

## Troubleshooting

| Problem | What to check |
| --- | --- |
| **No readable text found** | Confirm the page has visible text, reload it, and try again. Browser-internal and some protected pages cannot be read by extensions. |
| **Ollama connection failed** | Confirm Ollama is running and reachable at <code>http://localhost:11434</code>. Check the configured URL and local firewall. |
| **Ollama CORS / origin error** | On macOS, run the OLLAMA_ORIGINS command above before launching Ollama, then fully restart Ollama. |
| **Ollama returns 404** | Update Ollama, run <code>ollama pull phonon</code>, and confirm the selected model is phonon. |
| **Invalid WAV response** | Confirm Phonon is selected and the Ollama endpoint returns WAV audio. |
| **API authentication error** | Check the API key and whether your provider expects Bearer-token authentication. |
| **API returns 404** | Check the base URL, model availability, and whether the provider exposes POST /audio/speech. |
| **API returns HTML or JSON instead of audio** | Confirm the endpoint and model are correct and that the provider returns audio data rather than an error page. |
| **Test request times out** | Check the model server and endpoint. Settings tests have a 60-second timeout. |
| **Reading request times out** | Check the server and try a shorter text block. Reading requests have a 120-second timeout. |
| **Settings do not persist** | Check that extension storage is available, then reopen Settings and verify the selected provider and values. |
| **A page is read incorrectly** | Text extraction is heuristic. Complex layouts, repeated text, hidden content, or custom web apps may need page-specific handling. |

After updating a manually installed extension, open the browser's extensions page and click **Reload** on the WebsiteTTS extension card.

## Known limitations

- WebsiteTTS reads text available in the page DOM. It is not OCR and does not extract text from screenshots or images.
- Some browser-internal pages, protected pages, browser PDF viewers, and inaccessible cross-origin frames cannot be read.
- Text extraction uses semantic elements and visible div-content heuristics. Complex layouts can still produce missing, duplicated, or irrelevant text.
- The extension does not guarantee compatibility with every website or every OpenAI-compatible TTS implementation.
- The current distributable is a Chromium Manifest V3 package. Firefox and Safari are not supported by this release.
- Speech quality, available voices, model limits, latency, and provider-side data handling depend on the configured TTS service.

### Local development workflow

1. Clone the repository.
2. Open the cloned directory in your editor.
3. Load the directory in your browser using **Load unpacked**.
4. Make changes to the relevant source files.
5. Return to the extensions page and select **Reload**.
6. Re-test the popup, settings page, both provider paths, playback controls, and a page with embedded content.

There is no package installation or compilation step. The extension uses browser APIs and plain JavaScript, HTML, and CSS.

## Validation and releases

The GitHub Actions workflow validates pull requests targeting main and pushes to main. It checks the Manifest V3 configuration and required files, runs JavaScript syntax checks, and builds the Chromium ZIP and checksum as workflow artifacts.

Run the JavaScript syntax checks locally:

    node --check background.js
    node --check content.js
    node --check offscreen.js
    node --check popup.js
    node --check options.js

### Create a release

1. Update the version field in manifest.json.
2. Test the extension and merge the changes into main.
3. Create and push a tag matching the manifest version. For example:

       git tag v1.4.0
       git push origin v1.4.0

4. GitHub Actions validates the extension, creates the Chromium ZIP, generates a SHA-256 checksum file, and publishes a GitHub Release for tags beginning with v.
5. Download the ZIP and checksum from the release and verify the package before distributing it.

The workflow also uploads a ready-to-load unpacked folder and the ZIP/checksum as workflow artifacts. A manually triggered workflow run builds artifacts; GitHub Release publication runs for a pushed version tag.

**Browser stores are separate:** GitHub Releases do not submit the extension to the Chrome Web Store, Microsoft Edge Add-ons, Brave, or Opera. Store submission, listing details, screenshots, review, and publication must be handled separately by the publisher.
